# 通用财务问答：上下文、补取与临时计算

2026-10-08，按用户要求参考 Pi Agent Core，并允许交互 Agent 在归档缺数据时补取富途只读财务资料、自行编写简单计算代码。本次是现有 Agent 的可靠性收口，不增加 Agent、外部宿主或交易能力。

## 原因

原问题并不缺少归档数据：当前中国移动 run 包含 2023–2025/FY 的“销售毛利率”，还有同期间的重复来源。失败来自几处相互影响的通用问题：

- 总 token 预算同时累计每次请求的输入和输出，不能当作一次请求的上下文窗口。重复发送规则、Skill、大型结果，12,000 总额度不足以支撑实际多轮调用。
- 多个检索词原先被当作一个长子串；有资料也可能返回空。现在分隔的词按任一词命中，仍不是语义搜索。
- 工具结果、来源目录、引用与审计哈希直接挤入模型上下文；压缩还可能把最新工具结果全部丢掉，导致模型重查。
- 固定计算器仅支持四个公式，但旧提示和参数契约让模型误以为其他指标不能算；缺少按需联网工具。
- SQL 错误缺少可修正诊断，临时函数拒绝常用的推导式/`+=`，最终引用协议也未明确对象结构。

## 从 Pi 借鉴的边界

参照 [Pi Agent Core](https://github.com/earendil-works/pi/tree/main/packages/agent) 的 `transformContext → convertToLlm`，新增 Python `agent_context.py`：执行过程保留类型化记录，每次请求才选择用户目标、近期交互和工作记忆，再转换为模型消息。原始历史不被请求压缩修改；这不是完整进程恢复或新的事件重放系统。

参照 [ToolResult content/details](https://github.com/earendil-works/pi/blob/main/packages/agent/src/types.ts) 的分离思想，完整结果用于计算、归档和证据回执；模型只看到有界 JSON 投影。省略数量明确标出，不把事实截成半截 JSON；引用只投影最终协议需要的三个字段。投影按规则与问题的实际占用分配空间，压缩不能静默丢掉最新结果。不适配时明确预算失败。

新 Turn 默认总额度 30,000，仍为最多六次决策。本章实现时请求输入目标最多估算 5,000、输出上限 4,096；公司数据层 B 后按固定规则与最新结果动态调整单次输入，默认目标 5,000、最高 8,000（见 [B 实现](29-company-agent-query.md)），实际总消耗按 API usage 结算。总额度、请求容量与输出上限分别处理；既有 Turn 的预算不变，重试不刷新额度。最后一次决策提示模型收束并说明未完成部分。这些费用策略是本项目约束，不是 Pi 提供的保证；轻量估算也不是官方 tokenizer 或硬费用上限。

可纠正的工具参数、数据缺口和计算错误回送模型。SQL 返回隔离数据库的字段/语法诊断。相同成功调用可返回缓存一次，不重复执行；连续重复和连续三次工具错误仍停止。未知工具与越权仍失败。最终 JSON 与引用仍严格校验，不能因为模型声称算完就跳过校验。

## 数据与计算

模型根据当前问题自由选择路径，程序没有“中国移动/毛利率/平均值”专用分支：

1. `query_archived_financials` 查找实际指标及期间。
2. 缺原始数据时，`fetch_financial_data` 调用现有 `FutuFundamentalsProvider`。允许 statements（三表和关键指标）、operational_efficiency、revenue_breakdown；这是 API 权限目录，不是可计算指标目录。数据字段来自富途实际响应。
3. `run_readonly_sql` 在隔离 SQLite 快照上筛选/计算；保留 `fact_id` 才能取得计算输入引用。必要时用 `run_analysis_function` 执行模型编写的 `def analyze(rows)`，支持循环、常见推导式、`+=` 和受控内置函数。
4. Python 校验来源归属、来源哈希和当前 Turn 回执，然后生成临时报告；固定计算器仍只是四种快捷公式。

新问题默认允许上述只读补取，`allow_network=false` 明确禁止。权限来自冻结 Turn 的输入，不来自模型参数。补取只针对当前 ticker，用完关闭行情上下文；不能访问账户、交易、任意 URL、shell 或凭据。相同 Turn/数据集复用归档，不随关键词变化重复请求接口。当前 statements 沿用现有适配器的年度和数量限制，不承诺富途包含所有指标、历史期间或市场。

Tool Registry 升为 v4，analysis-workspace Skill 为 v4，interactive-research-agent 为 v2。已有显式冻结的旧授权不自动升级；旧版本 retry 若提示工具版本不匹配，应创建新问题，不能借重试刷新权限或预算。

补取文件位于 `data/stocks/<ticker>/agent-sources/<session>/<turn>/`，Source metadata 保存 session/turn、dataset、retrieved_at、available_from、币种与准则，原文有 SHA-256。来源不挂入正式 `run_sources`，因此不修改已冻结研究。只有当前 Turn 能通过补取范围引用它；后续新 Turn 不隐式混用旧快照，显式保存的 Memo 保留来源。新 SQL 包含新补取数据，旧 SQL/函数仍使用原快照。已有备份的来源文件枚举可覆盖这些文件；分析临时产物的完整备份仍属原审计中的后续事项。

代码只接触已选 SQL 行，不能 import、访问属性、任意函数、网络、环境或文件；继续使用独立子进程、10 秒、256 MB、64 KB 输出及每 Turn 六次 SQL/三次函数的限制。这是受限计算语言，不是任意 Python 沙箱。

## 实际验证与限制

- 离线集成测试使用固定计算器不认识的自定义指标，验证“检索无记录 → 模拟富途补取 → SQL → 模型提供的函数 → 引用回执 → 显式 Memo”，并检查正式 run/来源不变、跨 Turn 拒绝、缓存、离线禁止及连接失败恢复。
- 函数测试覆盖循环、推导式和增量赋值，继续拒绝 import/属性/动态执行；预算测试使用真实项目 Skill，累计输入和输出，并验证最新结果不会被压缩丢失。
- 真实 DeepSeek、主库只读备份的隔离副本：原“中国移动最近三年毛利率平均值”请求五轮完成，20,315 tokens。模型自行生成 SQL，选择 2023–2025/FY、CNY 的三条记录，并生成 Python 推导式计算平均值 58.624321666…；报告约 58.62%。其 final 仍附“未逐一核对年度”的保守缺口，说明最终文字完整性还有改进空间。
- 真实 DeepSeek + OpenD、全新临时库：无归档情况下主动调用富途，查询营业总收入，六轮生成回答，19,891 tokens。这次证明补取、归档与 SQL 查询通路；平均值由最终模型文字计算，没有执行聚合 SQL/函数，不能用它宣称计算工具调用遵循率已达标。
- 两次成功 smoke 的主库文件哈希均未变化，临时库随后删除。此前真实尝试曾遇到循环、语法和引用格式失败；本次不是重复成功率基准。后续单次模型仍可能选错口径、遗漏计算、耗尽轮数或返回不合格 JSON。

真实验证摘要保存在忽略的 `data/audits/20261008-multiturn/`；不包含 API Key 或隐藏推理。不改变正式研究验收结论，不自动保存 Memo，不提交数据或 Git。

下一步建议先建立 19E 小型跨场景基线，重点检查“缺数据是否补取、计算是否真正执行、期间/重复来源是否正确、引用是否完整、预算内是否完成”，再按结果优化检索和终答收束；记忆中文检索、共享索引和备份覆盖继续按架构审计分阶段处理。
