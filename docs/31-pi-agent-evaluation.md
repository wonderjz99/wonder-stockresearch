## 失败的实证原因

1. 模型未完成必要查询就结束。Q06/Q20复测首轮没有工具调用便返回缺口，Q24未查询就断言不能配对。结构合法的final仍可能是不合格答案。
2. 上下文投影和查询选择丢失有效信息。重复目录挤占facts；没有限定年度/字段的SQL只预览少量行，模型进而把省略当缺失；状态工具携带大型steps/draft_sections，使最新消息组也容纳不下。
3. 计算和语义验证有缺口。Q13没有调用计算工具，0.52405186%被心算成5.24%；Q20排序后年度配错；Q27标题和正文比例冲突；Q29均值基本正确，却把区间包含关系说成不重叠。引用存在不能证明解释正确。
4. unit/scale、披露日期确实可能缺失，但模型仍可能猜单位。也不能把SQL错误或英文关键词没有命中当作真实资料缺失。
5. 宽SQL、禁止属性调用等错误可以恢复，但模型不总会纠正。6轮/30,000tokens内未完成时，预算守卫正确停止；可用性仍未满足验收。

没有旧Agent同条件真实对照，不能把失败率归因于Pi SDK，也不宣称迁移造成或修复了全部研究质量问题。
