# 分阶段教学与交接约定

## 用户想怎样学习

每次实现一个可运行模块，由 Codex 完成代码和必要测试，然后写中文 Markdown 讲解。阶段完成后暂停，让用户阅读、提问、修改或要求下一阶段。不是只提供作业让用户自己写，也不是一口气做完整软件再补教程。

## 每章固定结构

1. 本阶段解决什么问题，与前一阶段如何连接。
2. 一个简单数据流图或调用图，不画尚不存在的组件。
3. 实际文件和入口函数，按一次输入到输出完整讲解。
4. 最小可运行示例及实际命令，说明结果和生成文件。
5. 为什么用这个实现；仅讲对当前代码有意义的 Python/SQL 概念。
6. 实际测试覆盖什么，以及仍不能证明什么。
7. 一个小练习，例如修改 fixture 或制造缺失引用；附预期现象，不强制用户完成后才能继续。
8. 已知限制与下一阶段将解决的问题。

代码要对应正式实现，不另造一套教学 harness、mock 框架或重复业务项目。fixture 可虚构，但必须标明为教学材料。

## 阶段结束记录

更新 PROGRESS：阶段号、文件、运行日期、命令、结果、未解决问题、下一步。README 中安装/使用命令随实际能力更新。用户改变需求时同步规格与决策记录，不把聊天作为唯一依据。

文档、测试命令与源码链接均相对项目目录；项目整体移动后不依赖旧绝对路径。当前只有交接资料，不创建空的 01–06 教学章冒充完成。
