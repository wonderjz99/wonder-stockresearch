### 2.1 用户追加：字段检索与明确工作清单（本轮验收）

- 字段位置不确定时，Skill、公共 system prompt 和工具说明一致要求先调用 `query_company_data(mode=fields, query=指标名)`，省略 dataset，在当前 Turn 获准范围内跨数据集定位；确认准确字段、原值/同比、期间类型后再定向取值。已有准确字段或用户明确限定数据集时无需强制多查一次；不绕过授权，不为 ROE 写硬编码流程。
- 沿用现有同义词搜索，目录默认仅列最近少量期间，并标明总覆盖数量、最早/最近期间和省略；详情从 facts/SQL 获取，模型分页按投影实际可见条目继续，目录仍不能作为证据引用。
- 由 Python 根据本 Turn 实际成功/错误/blocked 记录生成结构化工作清单，区分已完成、可用输入、当前错误、待办和续页；保留最近字段定位、查询 analysis_id、期间/值/单位样本、来源定位和成功计算结果。不同 Turn 的来源与状态不混入。
- 清单持久化到现有事件，重启可重建；下一次 legacy/Pi 模型请求均注入同样的业务清单。压缩优先缩短样本和旧交互，保留成功输入定位与当前错误；无需额外模型总结、向量库或新的记忆数据库。
- 验收覆盖：跨数据集找到指标、精确字段调用不多查、长期间目录明确省略和分页；超过两组工具交互后仍能看到已取得输入及下一步；压缩/重启后不丢关键定位、follow-up 不沿用旧 Turn 证据；脚本模型验证查询→计算→回答而非只检查 prompt 字符串。

保留现有 12 个允许函数。本轮不顺带开放任意方法调用、import、辅助函数、pandas/numpy 或一般 Python 执行；`zip` 等候选只有出现真实需求和验证用例时另行加入。文件/网络/环境/shell 权限、SQL 只读范围及来源归属检查不变。10 秒执行超时、12,000 字符代码上限、64 KiB 输出上限、每 Turn 最多三次实际函数执行及现有资源限制继续保留；平台可能不支持部分资源限制，不能宣称这是完整操作系统沙箱。

默认 runtime、thinking、历史报告和原 Pi 40/40 真实额度不变。新机会使用当前 Turn 剩余预算和轮数，不给 retry 或恢复执行补发额度。

## 3. 简单 Lambda 的允许范围

工程目标是支持常见排序 key，先实现最小且可验证的表达能力：

| 项目 | 本轮规则 |
| --- | --- |
| 出现位置 | 仅作为允许函数 `sorted(..., key=...)` 的直接 key 值 |
| 参数 | 一个普通位置参数；不允许默认参数、可变参数、关键字专用参数 |
| 可读取内容 | 该参数本身及其字段下标、常量；不捕获外层 rows、其他变量或内部对象 |
| 表达式 | 字段/常量、元组组合、已允许的基础算术和比较；数值/字符串转换只允许 `float/int/str` |
| 继续拒绝 | 属性/方法访问、其他函数调用、嵌套 Lambda、推导式、赋值表达式、动态调用和任意辅助函数 |
| 结果行为 | Python 原有排序行为；缺字段、类型冲突等产生真实执行错误，不自动猜字段或修补数据 |

已支持并通过离线测试的示例：

```python
def analyze(rows):
    ordered = sorted(rows, key=lambda row: row['period'])
    return {'periods': [row['period'] for row in ordered]}
```

应支持以 `float(row['value_decimal'])` 排数值，以及用元组组成多列排序 key。期间字符串排序是否符合财年顺序由输入契约决定，支持此语法不证明所有期间标签都可直接排序。

实现时为 Lambda 单独检查父节点位置、参数作用域和表达式；外层与 Lambda 内的调用规则分别验证。不能仅将 `ast.Lambda` 放进全局集合，不能跳过现有整棵语法树检查。同步检查允许函数名/保留名称的赋值遮蔽，避免模型代码改写内置函数后执行未预期调用。

函数允许列表、实际执行环境及给模型的说明应使用同一份小型能力定义或一致性检查，防止出现“文档说能用，执行时没有”的漂移。不引入通用插件或策略框架；旧的无 Lambda 函数继续可用。

## 4. 错误结果要告诉模型怎样改

沿用 `ToolFailure/ToolOutcome`，按需要以明确字段补充错误节点、行/列、阻止原因及上下文；内部诊断与有界模型投影分开。若增加字段，同步 Python 校验及 Pi 序列化，不拼接另一套错误协议。

反馈至少回答五件事：什么失败、失败在哪里、是否真的执行、原输入能否复用、下一步如何修改。例如：

```text
不支持该位置的 Lambda（第 X 行，第 Y 列）。代码尚未执行。
只支持 sorted(..., key=lambda row: row['字段']) 这类受限排序 key。
已有 SQL 输入 analysis_id=… 可继续使用，无需重新查询。
也可在 SQL 中 ORDER BY，或用无 Lambda 的排序写法。
```

根据实际错误生成提示：类型/字段缺失、语法不支持、执行失败、超时、预算耗尽不能共用一句“请重试”。语法拒绝不将成功 SQL 产物改为失败，也不占用三次实际函数执行额度；实际执行失败仍保留失败产物，不静默覆盖或把失败产物原位改成成功。

模型错误输出不放完整数据、密钥、隐藏推理或完整请求；下一步提示必须在投影后仍可见。对旧错误记录保持可读，不回写原 trace。

## 5. 重复失败后的继续规则

区分“工具是否执行”和“模型能否继续决策”，由公共 Python 执行层作出决定，两种 runtime 使用同一规则。

1. 第一次可纠正错误：返回具体错误及替代方案，保留成功输入和引用，进入原预算内的下一轮。
2. 模型再次提交同工具、同参数、且已知失败的请求：不执行，不改产物，记录 blocked；返回“你重复了同一失败请求，请修改代码或说明未完成部分”。每个 Turn 最多提供一次这种额外纠正反馈，不因换措辞、换 Attempt 或成功一次无关调用重置。
3. 模型提交已修改的合法代码：允许在原来源范围和执行额度内运行；这不是重放失败调用。修改后仍失败，沿用现有累计错误约束，不因参数哈希变化无限续命。
4. 额外机会耗尽、本 Turn 累计三次可恢复工具错误，或剩余轮数不足以完成工具后回答：在预算允许时进入只形成回答、不再调用工具的收尾决策。引用已核实事实，未完成计算写 gaps，不能伪造变化值或把计算失败记成计算成功。收尾仍可沿用既有引用修复机会，但不新增预算；模型违背无工具/协议规则仍终止。
5. 累计 token 或轮数已耗尽，不再额外请求模型；保存真实失败状态、已完成步骤和可恢复定位，向用户返回可读原因及会话关联。不能为了生成收尾回答突破预算。
6. 未授权工具、跨公司/Turn 访问、损坏来源、协议不一致等致命错误仍走原拒绝/终止路径，不通过纠正机会开放权限。成功重复查询保留既有缓存/复用语义，不扩大为无限成功调用循环。

现有三个停止点 `repeated_tool_call`、`repeated_analysis_error`、`analysis_tool_failures` 必须一起梳理，避免只改第一个，下一层仍提前抛出终止。收尾模式优先复用现有答案接收/引用校验能力；Pi 使用原生消息和工具钩子，legacy 使用现有循环，不另建调度器。

纠正机会及停止原因应从同一 Turn 的持久执行记录恢复。显式 retry、进程恢复和 follow-up 的区别需写清：retry 不重置本 Turn 额度；新 follow-up 是新 Turn，不能继承旧 Turn 的证据授权。

## 6. 已有输入、会话关联和观测

- 公共执行层在可恢复错误/blocked 时更新紧凑工作状态：最后一个可用 analysis_id、成功来源引用、错误码/位置、参数哈希、是否已执行、纠正机会是否使用、未完成动作。来自工具真实记录，不增加模型总结请求。
- 在下一次模型请求的辅助上下文中明确“数据已取得，只剩纠正计算”；legacy 的 `agent_context/agent_memory` 与 Pi 的 `pi_context` 都覆盖。已有事实若因大小省略，保留可读取的产物定位，不把摘录当成完整输入。
- chat 在业务执行开始前保存 Session/Turn 关联；失败、中断和成功都能定位原问题。恢复不误创建另一个问题，不自动刷新来源。
- 失败和执行前阻止都记录可追踪事件，关联 chat、Session、Turn、Attempt、runtime、原错误和参数哈希。只记录安全摘要；阻止不能显示成“工具成功运行”，不能用成功 span 掩盖真实失败。

## 8. 离线验收与交付顺序

所有用例使用虚构资料、隔离临时目录与脚本模型；真实 trace 只提供失败形态，不将私有原始内容复制进测试或 Git。

| 用例 | 必须证明的行为 |
| --- | --- |
| 简单排序 | 按期间、数值、多列元组排序正确；结果可 JSON 序列化，原输入及来源不变 |
| 不支持的 Lambda | 非 sorted key 位置、多参数/默认参数、外部变量、嵌套 Lambda、方法及未允许调用均被拒绝，指出实际节点/位置 |
| 既有能力 | 12 个允许函数与原 for/if/推导式用例继续可用；非法 import/属性访问/辅助函数不能借新能力执行 |
| 真实失败形态 | 原 trace 的排序 Lambda 通过新规则并完成计算；另造仍不支持的写法验证拒绝→反馈→修改→成功，而非继续期待原 Lambda 被拒绝 |
| 同参阻止后继续 | 第一次失败后原样重试不执行；模型收到 blocked 提示后修改，最终形成有引用的回答；两种 runtime 都覆盖 |
| 有限退出 | 反复提交同参、不断换失败参数、无关成功调用穿插，都不能无限恢复；预算足够时给诚实的未完成回答 |
| 预算与恢复 | token/轮数不足时不多发请求；retry/重启不补发纠正额度，实际函数执行计数不被 blocked 消耗 |
| 产物状态 | 语法拒绝保留 sql_succeeded；执行失败保留失败产物；跨 Turn 的 analysis_id 与引用拒绝；旧成功产物不覆盖 |
| 数据限制 | 缺字段、空输入、未知单位、类型冲突不能编造结果；成功数字仍能对应期间及合法引用 |
| chat/观测 | 失败前后 Session/Turn 关联完整；真正执行、语法拒绝、重复阻止可区分，安全摘要不泄漏正文或秘密 |
| 收尾校验 | 收尾禁用工具且经过原答案/引用校验；不得伪造计算成功，失败后也保留可查看的原问题状态 |
